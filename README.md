# 高度图转法线贴图

纯 Python 标准库实现的切线空间法线贴图生成器。读入 8 位灰度高度图 PNG，
输出单位长度、方向正确的 8 位 RGB 法线贴图 PNG。

```
python gen_samples.py
python -m normalmap.cli data/height.png --strength 1.0 --out normal.png
python -m pytest tests -q
python measure.py data/height.png normal.png
```

`height.png` 为 160x160：左侧一个半径 40 的圆台，右侧一条斜脊，两处外缘
都是码值非连续的突变边缘。`Gray`、`load_gray_png`、`save_png`、
`height_to_normal` 的名字与签名保持骨架原样，未引入任何第三方依赖。

## 1. 方向约定：OpenGL 切线空间，Y 向上

采用 **OpenGL 风格切线空间**（Y-up）：X 向右、Y 向上、Z 指向观察者，
平坦表面的法线 `(0,0,1)` 编码为 `(128,128,255)`。

高度图按屏幕坐标存储（行号 y 向下增大）。对表面 `z=h(x,y)`，由切向量
叉乘可得几何法线的水平分量与高度梯度反向：

```
nx = -dh/dx_screen
ny = +dh/dy_screen      # 屏幕 y 向下、切线空间 Y 向上，符号取正
nz = 1
```

因此峰顶**上方**的坡面 `ny>0`（G 通道 >128），下方坡面 `ny<0`
（G <128）；凸起（峰）与凹坑（高度取反）对应像素的 X/Y 分量严格反号，
颜色方向相反，浮雕不会再呈现凹陷感。若需 DirectX 风格（Y-down），
把 `ny` 反号即可，本项目固定使用 Y-up。

## 2. 长度：先归一化再量化

每条法线在浮点下除以自身模长，归一化为单位向量后才按
`round(n*0.5+0.5)*255` 量化为 8 位。浮点法线同时挂在返回对象的
`out.normals` 上，可无量化误差地校验。

`strength` 只线性缩放梯度（`gx = dh/dx * strength`），归一化保证向量
长度恒为 1，改变的只是倾斜角。实测同一点 `(90,1)`：

| strength | 倾斜角 | 浮点长度 |
|----------|--------|----------|
| 0.5 | 5.695° | 1.000000 |
| 1.0 | 11.279° | 1.000000 |
| 2.0 | 21.746° | 1.000000 |
| 4.0 | 38.581° | 1.000000 |

## 3. 边界：单侧差分，不钳制邻点

骨架在边界用 `max/min` 钳制邻点，斜坡贴边时边缘像素梯度变成 0，四周
出现一圈错误平坦区。现改为：

- 图像**内部**像素：中心差分 `(h[x+1]-h[x-1])/2`；
- **边缘**像素：前向或后向单侧差分，如左边界 `h[1]-h[0]`；
- 宽/高为 1 的退化情形梯度取 0。

单侧差分在真斜坡上给出与中心差分一致的梯度（仅差 8 位量化噪声，
测试容差 5e-3），因此斜坡贴边处依然倾斜，四周不再有成片平坦带。
纯背景的角落（如左上 30x30 无特征区域）法线仍严格为 `(0,0,1)`。

## 4. 突变边缘：归一化即防溢出

圆台外径与斜脊外缘存在码值突变。由于法线在编码前已归一化，三个分量
恒在 `[-1,1]`，编码时再做一次 `[0,255]` 钳制，任何 `strength` 下都
不会出现颜色溢出（实测全图字节范围 106–255）。中心差分的影响只波及
突变线外侧紧邻的 1 像素邻接环（实测背景中非正上方像素距最近特征边缘
不超过 0.8 像素），属于差分算子的正常作用范围，不是平坦带。

## 5. 色彩空间

### 输入：先 sRGB 解码，再求梯度

8 位高度码值按 sRGB 传输函数（IEC 61966-2-1）解码为线性光值后再求
梯度：

```
c <= 0.04045 :  lin = c / 12.92
否则          :  lin = ((c + 0.055) / 1.055) ** 2.4
```

骨架直接拿 sRGB 码值当线性值，斜坡坡度整体偏小（sRGB 中段码值 128
对应线性值仅约 0.216）。`strength` 在线性梯度上施加。

### 输出：线性 PNG，读回不做二次转换

法线数据是线性向量，输出 PNG 写入两个声明块：

- `gAMA`：gamma = 1.0（块值 100000）；
- `cHRM`：sRGB/BT.709 原色与白点色度。

即明确声明该文件为线性数据。合规读取方见到 gAMA=1.0 不会再做 gamma
转换；本项目自带的 `load_rgb_png` 也只做原始字节读取、不施加任何
色彩变换，实测写盘前后 RGB 字节**完全一致**（字节级往返相等）。

## 6. 实测结果（strength=1.0，data/height.png）

由 `python measure.py data/height.png normal.png` 得到：

**全图法线长度**

| 数据源 | 最小长度 | 最大长度 |
|--------|----------|----------|
| 量化前浮点法线 | 1.000000 | 1.000000 |
| PNG 读回的 8 位法线 | 0.991498 | 1.001345 |

浮点长度误差为 0（远优于 1e-3）；8 位量化后的长度偏差最大约 0.0085，
属于单字节量化固有误差。

**倾斜角（法线与 +Z 轴夹角 `acos(nz)`）**

| 位置 | 倾斜角 |
|------|--------|
| 圆台坡面最大处 `(70,69)` | 3.207° |
| 圆台半径 ≈10 的坡面代表点 | 2.402° |
| 圆台外缘环带（d=30~38）最大 | 0.582° |
| 斜脊坡面最大处 `(90,1)` 等 | 11.279° |
| 斜脊外缘（圆台外突变线）最大 | 0.122° |

圆台坡度偏小是 sRGB 线性化的正确结果：其码值随半径线性下降，而线性
光值在暗部变化很缓（理论核算 d=10 处约 2.2–2.4°，与实测一致）。

## 7. 测试覆盖

`tests/test_basic.py` 共 15 个用例，覆盖：

- 平面区域法线严格指向正上方（浮点 `(0,0,1)`、编码 `(128,128,255)`）；
- 凸起与凹陷方向相反（X/Y 分量逐像素反号），并校验 Y-up 编码方向；
- 全部法线单位长度（误差 ≤1e-3），`strength` 改变倾斜角但不改变长度；
- 边界单侧差分：线性斜坡贴边仍倾斜、无平坦带，平坦图边界保持正上方；
- 突变边缘大 `strength` 下分量不超界、字节不溢出；
- sRGB 解码正确性、梯度确实基于线性值；
- 输出 PNG 带 gAMA/cHRM 线性声明，RGB 字节级往返一致。

```
$ python -m pytest tests -q
15 passed
```
